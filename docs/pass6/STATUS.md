# Pass 6: phones and tablets, menus, G'MIC, parity sweep, speed, deployment

Results are from the promoted engine (118.8 MB raw, 29.8 MB brotli) unless a line says otherwise.
Earlier state: `docs/pass5/STATUS.md`. Speed and size: `docs/speed/REPORT.md`.

## Added

- **Phone and tablet interface** (`web/src/mobile/`): chosen from pointer type and screen size
  (`?ui=desktop|tablet|phone` overrides, also a setting). Canvas-first layout, bottom or side
  sheets for layers, colour, brushes, tool options and Krita's dockers, a tool strip with every
  Krita tool behind "more", thumb sliders for size and opacity. One finger paints, two fingers
  pinch, rotate and pan, two-finger tap undoes, three-finger tap redoes, long-press picks a colour,
  touch is ignored for painting just after a pen. On-screen Shift/Ctrl/Alt and Apply/Cancel for
  Krita tools; Krita dialogs fit the screen and have a keyboard button.
- **Krita's menus in the page** (`web/src/krita/menus*.ts`, generated by
  `web/scripts/gen-krita-menus.mjs` from Krita's own menu files): 195 Krita entries in nested
  submenus, with labels, enabled state, check marks and shortcuts from the engine, on desktop and in
  the phone command list. Left out: entries that open file dialogs onto the in-memory disk, window
  and quit entries, and three actions the engine refuses (below).
- **G'MIC** (Filter > Start G'MIC-Qt): the real dialog with 645 filters; filters apply and undo.
  No network use. About 8 s the first time the dialog opens.
- **Krita's on-canvas messages** are shown as a short toast.
- **Unsupported browsers** get a readable message instead of a blank page.
- **Toolbox order** follows Krita's own tool priority.
- **Cloudflare Worker** fixed and tested locally; `deploy/README.md` has upload steps and a checklist.

## Fixed

- **Undo could restore only part of the image.** Krita could not read the memory size, assumed
  1 GB, and swapped tile data (undo included) to a file that read back blank. It is now told 3 GiB
  and keeps tile data in memory.
- **A fast pen could leave the engine stuck.** Requests from the page are now handled one at a time,
  except input for Krita's own windows and anything arriving while a Krita dialog is modal.
- **Krita's fatal assertions** on its own thread become an error for the request instead of killing
  the engine ("Split Alpha > Write as Alpha" on the wrong layer type now reports an error).
- **Add Fill Layer crash:** two plugins had an interface class of the same name; one is renamed.
  Krita's dialog now opens, but see known problems.
- **Two small inputs** in the phone panel sheet were under the touch-size minimum.

## Known problems

- **Three Krita actions are refused by the engine** with a message: Add Fill Layer (Krita's dialog
  opens, then the engine stops answering; the page has its own Add Fill Layer), Add Color Overlay
  Mask (takes the tab down; no stack obtained), Convert to Filter Mask (its dialog cannot be closed).
- **115 actions had no visible effect in the sweep.** Many need a context the sweep did not set up
  (a selection, a vector layer, an animation); they were not checked one by one.
- **G'MIC:** to fit the compiler's memory limit, about 35 internal error handlers in its interpreter
  no longer catch (mostly 3D and file fallbacks). Colour-picker and file parameters, the Apply
  button and "repeat last filter" were not tried.
- **Phones:** memory is the risk. WebKitGTK used about 2.4 GB for an empty document; iPhones
  typically allow a tab less. Nothing was run on a real phone or tablet, with a real pen, or on a
  real on-screen keyboard. Typing into a Krita dialog field through the keyboard button was not confirmed.
- **Browsers:** only Chromium was really tested. Firefox could not be installed here. WebKitGTK (the
  nearest stand-in for Safari) needs a launch option to expose shared memory; real Safari was not tested.
- **Engine waits on the page's thread** for file reads and timers (see the speed report).
- **Transform handles** can be missing if the tool is picked within about two seconds of start-up.
- **Cloudflare:** tested locally only. Edge behaviour for the precompressed files and the zone's
  settings need the real account.
- **Unit tests:** four off-by-one failures still need a desktop comparison.
